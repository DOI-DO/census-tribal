Census Tribal Data

Background

The purpose of this document is to describe the Census Bureau’s American Community Survey (ACS) products that are available for American Indian/Alaska Native/Native Hawaiian (AIANNH or “Tribal”) geographies, and how these data can be accessed using the Census API.

Care needs to be exercised in using Census data on Tribal geographies to describe Tribal populations, particularly in instances where high proportions of non-Tribal members reside within the boundaries of the Tribal geography. According to the Census Bureau, “ACS [American Community Survey] data users…need to understand that many American Indian and Alaska Native areas have substantial populations that are neither American Indian nor Alaska Native.”1 For example, data from the Census Bureau’s My Tribal Area tool “provide characteristics for the entire population living in the AIAN area (regardless of their race or whether people identify as American Indian or Alaska Native).”2

For this reason, whenever possible, data at the Tribal geography level should be broken out by race/ethnicity for purposes related to describing Tribal populations. However, not all ACS topics in the Census Bureau’s data.census.gov are disaggregated by race/ethnicity.3 Examples in this document will assist the reader in finding Census ACS data for Tribal geographies that is also disaggregated by race/ethnicity.

Specifically, this document focuses on Census products that have an associated API and that are available for American Indian/Alaska Native/Native Hawaiian (AIANNH) geographies. This limits the universe of available Census data to those that are derived from ACS 5-year estimates (due to the population size of most AIANNH geographies). APIs are provided for the Detailed Tables, Subject Tables, Data Profiles, and Comparison Profiles but Comparison Profiles are not available for AIANNH geographies. Therefore, the code in this document is tailored for pulling ACS 5-year data from the Detailed Tables, Subject Tables, and Data Profiles only. The figure on page 23 of this Census presentation summarizes the differences in these products.4

Constructing API Calls from Census

Get an API key

Census technically does not require users to have an API key but there can be limits on the number of requests coming from your IP address if you don’t use it. It’s quick and easy to request one: https://api.census.gov/data/key_signup.html.

Pull an entire table using the API

API calls can be constructed to either pull an entire table, analogous to downloading a table from data.census.gov, or to pull specific variables. In this example, we will pull the table B01001: Sex by Age from the AIAN Detailed Tables. You can view this table in data.census.gov here. This version includes all AIANNH geographies and data on “All available races alone or in combination”. When you view the table in data.census.gov, you will see an “API” button in the header above the table, which provides the API endpoint. You could copy/paste this endpoint into any web browser and you will see the data the table contains. Essentially what you are doing when you construct an API call is you are creating that endpoint, and then pulling the data into your R environment and making it a tidy data frame so the data are usable.

In this example, if you click on the API button when you open the table in data.census.gov, you’ll get this:

https://api.census.gov/data/2021/acs/acs5/aian?get=group(B01001)&POPGROUP=pseudo(-02)&ucgid=pseudo(0100000US$2500000)

That url can be broken down into some general parts that will exist across the different tables:

There are a few things to understand about these different parts:

  1. Pop group iteration codes

  • Uses iteration codes which are NOT the same as Census’ race/ethnicity codes

  • Can specify exact codes or use “pseudo()” codes:

    • pseudo(-00) == “All available races” – this will show AIAN-A, AIAN-AoIC, and any specific tribal groups alone or in combination

    • pseudo(-01) == “All available races alone” – this will show only AIAN-A

    • pseudo(-02) == “All available races alone or in combination” – this will show only AIAN-AoIC

    • For pulling both AIAN-A and AIAN-AoIC without the specific tribal groupings, use pseudo(-01, -02) – this is equivalent to pulling POPGROUPs 006 and 009 (see iteration codes)

  1. Geographic codes

  • Uses GEO_ID in the form of “ucgid = {GEO_ID}”

    • Ex for Navajo Nation, would specify “ucgid=2500000US2430”

  • For pulling multiple geographies, again uses the “pseudo()” code concept:

    • All AIANNH: pseudo(0100000US$2500000)

    • Only Alaska Native Regional Corporations (ANRCs): pseudo(0400000US02$2300000)

We can put this all together into some code examples. These examples use the r packages httr and jsonlite to help construct the endpoints and then pull the data, rvest for reading in html content, and tidyverse for general tidy coding. If necessary, run install.packages(c('tidyverse', 'httr', 'jsonlite', 'rvest')) to install these packages before moving on.

# Call necessary packages
library(tidyverse)
library(httr)
library(jsonlite)
library(rvest)

Example 1: Pull the B01001 table from the American Indian Alaska Native Tables (AIANT) for all tribal geographies and for the race/ethnicities “All available races alone or in combination”

# Pull the data from the specific endpoint
# Note: API key is not used in this example
response <- GET('https://api.census.gov/data/2021/acs/acs5/aian?get=group(B01001)&POPGROUP=pseudo(-02)&ucgid=pseudo(0100000US$2500000)')
data <- fromJSON(content(response, "text"))

# Convert to data frame
df <- as.data.frame(data, stringsAsFactors = FALSE)
names(df) <- df[1, ]
df <- df[-1, ]

# Move identifying variables to the top of the df
df <- relocate(df, 'GEO_ID', 'NAME', 'POPGROUP', 'POPGROUP_LABEL')

It’s hard to understand what exactly is being shown in this table but before diving into understanding the variables, let’s look another simplified example of pulling an entire table from the AIANT.

One thing to note about these examples is that when you pull an entire table, the dataframe that you end up is a transposition of the table as viewed in data.census.gov (that is, what appears as rows in the data.census.gov table are columns - variables - in the dataframe). This will be helpful to know for constructing API calls that pull a specific variable, covered in the next section.

Pull specific variables from a table

If you look at the variable names of all the examples from the previous section, you’ll notice that they all follow a similar pattern. First there are the identifying variables (GEO_ID, NAME, POPGROUP, POPGROUP_LABEL) - these typically default to the end of the dataframe and moving them to the front is the final step in the code, since that makes the data easier to read and use. After that, the variables have names that seem nonintuitive such as “B01001_001E”. All variables in the Census ACS APIs geneally follow the same naming structure:5

{table ID}_{line number}{estimate type}

However, there are nuances and variations within this general format. Reading the section on “Understanding Variable Names” in the Census API Handbook (starting on page 7) is recommended.

“Estimate type” values are:

  • “E” refers to a numeric representation of the ACS estimate.

  • “M” refers to a numeric representation of the margin of error.

  • “PE” refers to an estimate representing a percent of the total.

  • “PM” refers to the margin of error for a percentage.

  • Anything with an “A” at the end refers to a special annotation of that estimate type (e.g. EA means an estimate annotation).

In the examples above:

  • B01001 = table ID (Sex by Age)

  • 001 through 049 = the table line numbers, where 001 corresponds with the first line (Total) and 049 corresponds with the last line (85 years and over)

  • E = estimate, M = margin of error (MoE), EA and MA are annotations for those

This means that if you know the table that contains a specific variable you are interested in, you can construct the API call to pull just that variable, and you can determine the variable name based on the information that you know about it (table ID, row number, estimate type).

In the following examples, we will use a more dynamic form for constructing the API endpoint and eventually create a generalized function to construct the endpoint.

Example 4: Pull the top line of the B01001 table from the AIANT for all race/ethnicities and for all Tribal geographies

In this example, we are interested in data similar to what we were looking at in Example 3, but we just need the total population estimates for all of the race/ethnicities (including Tribal groupings), not the breakouts by sex or age. However, we also want this data for all Tribal geographies.

Since we are interested in the top line, we know this is row number 001. The table is the same as the previous examples - B01001. We are interested in the estimate (E) and let’s say we also want MoE (M). Putting this together, the variables we want to pull along with the identifying variables (GEO_ID, NAME, POPGROUP, POPGROUP_LABEL) are: B01001_001E and B01001_001M.

# List the variables WITHOUT spaces between the variable names
variables <- 'GEO_ID,NAME,POPGROUP,POPGROUP_LABEL,B01001_001E,B01001_001M'
# In this example, we are using the AIANT so the most recent year is 2021
year <- '2021'

base_url <- paste0("https://api.census.gov/data/", year, "/acs/acs5/aian")
  query <- list(
    get = variables,
    "for" = "american indian area/alaska native area/hawaiian home land:*",
    key = census_api_key # defined in a previous step 
  )

  # Make request
  response <- GET(base_url, query = query)
  data <- fromJSON(content(response, "text"))

  # Convert to data frame
  df <- as.data.frame(data, stringsAsFactors = FALSE)
  names(df) <- df[1, ]
  df <- df[-1, ]
  
# Move identifying variables to the top of the df
df <- relocate(df, 'GEO_ID', 'NAME', 'POPGROUP', 'POPGROUP_LABEL')

Pull specific variables without using a table

Finding a specific variable that you are interested in does not require going through a bunch of tables in data.census.gov and locating the variable you need and then figuring out its row number and constructing the variable name from that. Census provides a full list of variables for each set of tables/profiles that can be viewed at the links below:

Data Profile Variables (https://api.census.gov/data/2023/acs/acs5/profile/variables.html)

Subject Table Variables (https://api.census.gov/data/2023/acs/acs5/subject/variables.html)

AIAN Table Variables (https://api.census.gov/data/2021/acs/acs5/aian/variables.html)

Detailed Table Variables (https://api.census.gov/data/2023/acs/acs5/variables.html)

For the Data Profiles and Subject Tables, we can read these tables into dataframes and, since we are interested in variables that specifically apply to American Indian and Alaska Native populations, filter for variables that contain the string ‘American Indian and Alaska Native’.

Example 5: Pull variables from a Data Profile table for total population, AIAN alone population, and AIAN alone or in combination population for all Tribal geographies

Data Profiles provide summaries of ACS data for various social, economic, housing, and demographic characteristics for the United States, regions, divisions, states, counties, county subdivisions, places, metropolitan areas, American Indian and Alaska Native areas, and other geographic areas. ACS Data Profiles begin with the letters “DP.”6

The code chunk below pulls all of the variables that are in the Data Profile tables and then filters for the ones that include “American Indian and Alaska Native”.

# Data Profile variables

# URL of the variables page 
url <- "https://api.census.gov/data/2023/acs/acs5/profile/variables.html"  

# Read the HTML content 
page <- read_html(url)

# Extract all tables from the page 
tables <- page |>
  html_elements("table")  

# Convert the table to a data frame 
variables_df <- tables[[1]] |>    
  html_table(fill = TRUE) |>   
  tibble::as_tibble(.name_repair = "unique") |>   
  slice(-1) |>   
  select(-last_col())  

# filter to only AIAN 
dpvar_aian <- variables_df |>   
  filter(str_detect(Label, "American Indian and Alaska Native"))

rm(url, page, tables)

Notice that all of the AIAN variables start with DP05 - that’s because only the table “DP05: ACS Demographic and Housing Estimates” contains race data. We can adapt the previous example to pull specific variables from this table. For example, we can pull population estimates and their MoEs for each Tribal geography for:

  • Total population (row 0001)

  • One race - AIAN (row 0039)

  • Race alone or in combination with one or more other races - AIAN (row 0071)

Putting together what we know about variable name construction, these would have the variable names: DP05_0001E/M, DP05_0039E/M, and DP05_0071E/M. Also, the POPGROUP concept only applies to the AIANT or other special population tables, so the POPGROUP and POPGROUP_LABEL variables have been removed in the code below.

# List the variables WITHOUT spaces between the variable names
variables <- 'GEO_ID,NAME,DP05_0001E,DP05_0001M,DP05_0039E,DP05_0039M,DP05_0071E,DP05_0071M'
# In this example, we are using the Data Profiles so the most recent year is 2023
year <- '2023'

# base url has a slightly different form than the AIANT so this is different from the past examples
base_url <- paste0("https://api.census.gov/data/", year, "/acs/acs5/profile")
  query <- list(
    get = variables,
    "for" = "american indian area/alaska native area/hawaiian home land:*",
    key = census_api_key # defined in a previous step 
  )

  # Make request
  response <- GET(base_url, query = query)
  data <- fromJSON(content(response, "text"))

  # Convert to data frame
  df <- as.data.frame(data, stringsAsFactors = FALSE)
  names(df) <- df[1, ]
  df <- df[-1, ]
  
# Move identifying variables to the top of the df
df <- relocate(df, 'GEO_ID', 'NAME')

Example 6: Pull variables from a Subject Table table for total population and AIAN populations for all Tribal geographies

Subject Tables include ACS data organized by subject area, providing an overview of the information that analysts most often receive requests for from data users. ACS Subject Tables begin with the letter “S.”7

There are a lot of Subject Tables and corresponding variables, and the variables also have a slightly different structure to their names than with the other table types. Many (all?) of these tables are cross-tabulations, where there are multiple columns per geography. For example, if you look at Table S1903 (in this example, for the Navajo Nation), you can see there are three column headings for which estimates and MoEs are presented: Number, Percent Distribution, and Median Income. These column headers translate to the variable names as a component that comes after the Table ID and begins with “C” and is followed by a two-digit, sequential number starting with 01. Specifically, the Subject Table variable names take the format: {table ID}_{column header}_{line number}{estimate type}. In this example, if we wanted to pull a specific row for Median Income (the third column header), the variable name would take the form S1903_C03_(row number of variable)(E/M).

Because there are so many variables within the Subject Tables, and the added layer of multiple columns, the best approach to using these may be to examine the list of variables and searching in the Concept field for a specific subject matter, and seeing if there is a racial breakout for that subject matter. For example, the code below will produce two dataframes: one with all of the Subject Table variables (“subvar_all”) and one with just the Subject Table variables that contain the string “American Indian and Alaska Native” in the Label field (“subvar_aian”).

# Subject Table variables

# URL of the variables page 
url <- "https://api.census.gov/data/2023/acs/acs5/subject/variables.html"  

# Read the HTML content 
page <- read_html(url)

# Extract all tables from the page 
tables <- page |>
  html_elements("table")  

# Convert the table to a data frame 
subvar_all <- tables[[1]] |>    
  html_table(fill = TRUE) |>   
  tibble::as_tibble(.name_repair = "unique") |>   
  slice(-1) |>   
  select(-last_col())  

# filter to only AIAN 
subvar_aian <- subvar_all |>   
  filter(str_detect(Label, "American Indian and Alaska Native"))

rm(url, page, tables)

Let’s say we are interested in measures of median income in Tribal geographies. Searching the Concept field (using the built-in filter function in R Studio when viewing the subvar_all dataframe), we can see that there is a table (S1903) with a column header on Median income (C03) where the first row (001E) is “Estimate!!Median income (dollars)!!HOUSEHOLD INCOME BY RACE AND HISPANIC OR LATINO ORIGIN OF HOUSEHOLDER!!Households” and where another row within that table group (S1903_C03_004E) is “Estimate!!Median income (dollars)!!HOUSEHOLD INCOME BY RACE AND HISPANIC OR LATINO ORIGIN OF HOUSEHOLDER!!Households!!One race–!!American Indian and Alaska Native”. We could pull both of those to view not only the median income of the households that identify as AIAN alone but also how that compares to the median income of all households in that Tribal geography, in case there is a significant proportion of non-Tribal members living within a geography.

When we examine the resulting data, we see there are instances where the value is “-666666666”. It’s not obvious what this means (something satanic?) but if you inspect the same base table in data.census.gov (in this example, S1903) for Tribal geographies, you will see dashes for some of those geographies which indicates “The estimate could not be computed because there were an insufficient number of sample observations. For a ratio of medians estimate, one or both of the median estimates falls in the lowest interval or highest interval of an open-ended distribution. For a 5-year median estimate, the margin of error associated with a median was larger than the median itself.” Essentially, it means those data are not available.

Example 7: View AIAN Table variables

The AIAN Tables are released as part of the Selected Population Tables, which are released every five years and provide the greatest level of statistical detail for specific population groups. The AIAN Tables show more detailed Tribal categories than the Selected Population Tables.8 However, because it is only released every five years, the most recent data available are from 2021.

For the AIAN Tables, all variables can be broken out by various types of American Indian and Alaska Native identifiers or Tribal groups (the POPGROUP concept discussed in examples 1 through 4) so any of the variables available in the AIANT endpoint can be augmented using POPGROUP to view specific AIAN/Tribal grouping estimates. The code chunk below is for creating a dataframe of all variables in these tables; for example on pulling variables from this endpoint, refer to examples 1 through 4.

# AIAN Table variables

url <- "https://api.census.gov/data/2021/acs/acs5/aian/variables.html"

# Read the HTML content 
page <- read_html(url)

# Extract all tables from the page 
tables <- page |>
  html_elements("table")  

# Convert the table to a data frame 
aiantvar <- tables[[1]] |>    
  html_table(fill = TRUE) |>   
  tibble::as_tibble(.name_repair = "unique") |>   
  slice(-1) |>   
  select(-last_col())

rm(page, tables)

Example 8: Pull data on Median Age of AIAN Alone populations from all Tribal geographies from a Detailed Table

Detailed Tables provide access to the most comprehensive ACS data tables on all topics and geographic areas. They begin with the letters “B” for base tables and “C” for collapsed tables. The “collapsed” tables cover the same topics as the base table, but with fewer categories.9 In addition, the table ID sometimes ends with the letter A through I - these indicate tables that are broken out for specific race/ethnicity categories, where “C” corresponds with the race/ethnicity category “American Indian and Alaska Native Alone”. If using these tables, it is a best practice to first compare the estimates of American Indian and Alaska Native Alone with American Indian and Alaska Native Alone or in Combination for that geography (using table DP05) in order to determine whether the geography has a significant portion of potential Tribal members who are identifying as multiracial.

Otherwise, the format of these variables takes the same general form that has been used in most of the other tables: {TableID}_{Row Number}{Estimate Type}. Similar to what was done for the Subject Tables, a user could approach these tables by viewing and filtering dataframes of the variables to find those that contain a topic of interest, and seeing if there is a racial breakout. The code below will produce two dataframes: one with all of the Detailed Table variables (“dtvar_all”) and one with just the Detailed Table variables that contain the string “American Indian and Alaska Native” in the Label or Concept fields (“dtvar_aian”).

# Detailed Table variables

url <- "https://api.census.gov/data/2023/acs/acs5/variables.html"

# Read the HTML content 
page <- read_html(url)

# Extract all tables from the page 
tables <- page |>
  html_elements("table")  

# Convert the first table to a data frame 
dtvar_all <- tables[[1]] |>    
  html_table(fill = TRUE) |>   
  tibble::as_tibble(.name_repair = "unique") |>   
  slice(-1) |>   
  select(-last_col())

# filter to only AIAN 
# The Detailed Tables differ from the Subject Tables and Data Profiles in that race can appear in both the Label field and the Concept field
dtvar_aian <- dtvar_all |>   
  filter(str_detect(Label, "American Indian and Alaska Native") | str_detect(Concept, "American Indian and Alaska Native"))

rm(page, tables, url)

It’s a good idea to use the advanced search tool for data.census.gov (https://data.census.gov/advanced) to get a sense for what kinds of data are available for the topic you are interested in, because there may be multiple tables that address that topic and those tables may be available for different geographies. For example, though data on AIAN populations working from home were not available for Tribal geographies through the Detailed Tables, using the advanced search tool would point you to a Subject Table (S0802) that has similar types of data for Tribal geographies that could potentially be used instead.
